# ReefLive — 3D Asset Specification (Blender `bpy` scripts)

All assets are generated by Python scripts in `tools/blender/` run with the headless `bpy` module (`/tmp/claude-0/bpyenv/bin/python tools/blender/build_all.py`). Outputs are committed under `app/src/main/assets/models/` (GLB) and `app/src/main/assets/textures/` (PNG). No manual Blender work; everything must be reproducible from the scripts.

Coordinate frame: world cm, origin at the inside bottom-front-left corner, +X right, +Y up, +Z toward the viewer (glTF is Y-up so export with `export_yup=True` from Blender's Z-up scene: build the scene in Blender with Z up and the exporter converts; script authors must think in "Blender Z = world Y"). Tank interior: 121.9 × 33.0 × 61.0 cm; sand top at 3 cm; water at 56 cm.

Export settings (shared `common.export_glb(path, objects)` helper, Blender 5.2 exporter): `bpy.ops.export_scene.gltf(filepath, export_format='GLB', use_selection=True, export_apply=True, export_yup=True, export_texcoords=True, export_normals=True, export_vertex_color='NAME', export_vertex_color_name='Col', export_all_vertex_colors=False, export_materials='EXPORT', export_image_format='AUTO', export_animations=False, export_skins=False, export_morph=False, export_extras=True, export_tangents=False, export_cameras=False, export_lights=False)`. PNG images are embedded verbatim (no re-encode). Custom data is passed via object **and** mesh custom properties (→ node and mesh `extras`): `part`, `anchor` (name), `species`, `instances`, plus per-asset keys listed below.

**Allowed `extras.part` values** (the renderer picks the shader by part): `body`, `fin`, `eye`, `jaw` (reserved; no current model uses it), `polyp` (instanced polyp prototype), `antenna`, `shell`, `leg`, `tube` (feather-duster tube), `card` (alpha-tested algae cards), `rock`, `sand`, `glass`, `backglass`, `water`, `rim`, `stand`, `equipment`, `light` (fixed emissive, e.g. heater LED), `emitter` (AI Prime lens whose emissive follows the light color). `tools/validate_glb.py` rejects anything else.

Vertex color channel `Col` (COLOR_0) is **data, not color**. The Blender 5.2 exporter writes it as `VEC4` **unsigned-short normalized** (not float) and keeps it linear; loaders must normalize. Per asset family:
- **fish / mobile inverts**: R = 0, G = gill/opercular mask, B = fin hinge (0 at the fin base → 1 at the tip; also antenna/leg flex), **A = spine coordinate: 0 at the snout (+X end, x = +0.5) → 1 at the tail tip (x = −0.5)**, i.e. A = 0.5 − x. (Fish face +X, so A *decreases* along +X; PLAN.md's "0→1 along +X" wording is superseded by this.) Fins and eyes carry the A of their base/attachment point.
- **limb-rigged crawlers** (`brittle_star.glb`, `sally_lightfoot.glb`; SIMULATION §19): limb vertices (part `leg`) carry **R = t along the limb** (0 at the root → 1 at the tip), G = 0, **B = limb index / 9** (star arms 0–4; crab legs k = 2·pair + (0 left, 1 right), pair 0 at the front; chelae 8 left, 9 right), A = 0.5 − x. The limb nodes (Arms; Legs and Claws) and Root carry **`extras.limbPivots`**: 10 × vec4 in glTF model space (xyz = limb root, w = rest limb length; unused slots 0). `fish.vert` poses each limb about its pivot from `OrganismPose.limbs` when `uLimbOn` is set; `tools/blender/limbpose.py` mirrors that for previews and cards. Limbs are modelled straight (star) or in a neutral stance (crab); the pose comes from the sim.
- **shrimp limbs** (`shrimp.glb`, `skunk_shrimp.glb`): limb vertices use R = limb class / 8 instead of R = 0, G = pair / 8, B = hinge; see §2.8 "Limb rig". They have no `limbPivots`; the same `uLimb[]` channel carries one entry of whole-animal signals.
- **corals** (`body`): R = thickness proxy (1 thin/translucent … 0 thick), G = sway-group phase (0..1), B = sway weight (0 at the attachment → 1 at free tips), A = 1. Polyp prototypes: B = tentacle hinge 0 → 1, A = 1. Cards: B = 0 root → 1 tip.
- **sand**: R = green film mask along the front glass; others 0, A = 1. Rock: (0, 0, 0, 1) (hair-algae mask lives in the albedo alpha).
- **static details** (`reef_details.glb`, §4.1): `body` nodes use the coral layout with **B = 0 everywhere** (nothing sways; R = thickness, G = clump phase); `equipment` / `backglass` nodes (0, 0, 0, 1).

## 1. Fish and shrimp: shared procedural method (`tools/blender/fishlib.py`)

### 1.1 Loft body
> **As built** (`fishlib.build_body`): no Subdivision pass. The loft is built directly at the target density: `stations = tris / (2 × ring)` stations spaced with a cosine bias toward snout and tail, each a **superellipse** ring (32 verts; flatter flanks via exponent 0.85, wider below the lateral line `belly_bias`, pinched dorsal ridge `back_pinch`), interpolated with monotone **PCHIP** through the profile table (no overshoot), snout/tail closed with fans. **Body UV**: u = body coordinate (0 snout … 1 caudal peduncle), **v = flank height** (0 ventral midline, 0.5 lateral line, 1 dorsal ridge); both flanks map to the same texels (mirrored, so the texture has no seam and paints like a left-facing side view with the back at the top). Body texture 1024×512 (engineer goby 2048×256). The caudal fin is a separate mesh beyond u = 1; the export transform scales the whole fish (snout … caudal tip) to exactly length 1, centred, snout at x = +0.5.

Original plan (superseded):
```
build_body(profiles, length_cm, segments=48, ring_verts=20) -> Mesh
  profiles: list of (u, height_ratio, width_ratio, y_center_offset) sampled along u ∈ [0,1]
  For each of 48 stations along +X (u = i/47), create a ring of 20 vertices: ellipse with
  half-height = height_ratio(u) × L/2, half-width = width_ratio(u) × L/2, center shifted by y_center_offset(u) × L
  (ratios interpolated with Catmull-Rom through the profile table). Rings joined into quads; snout and tail capped
  with a 3-ring fan. Then apply Subdivision (1 level, Catmull-Clark) → ~3.8k tris; shade smooth; UV: cylindrical
  (u along length, v around; seam along the belly) so the texture is painted in a flat "unrolled" space.
  Vertex color A = u.  G = opercular mask: 1 inside the ellipse centered at u∈[0.17,0.26], lower half, feathered.
```
Profile tables below are (u, height, width, yOffset) with ratios relative to body length L; `height` is full body depth / L, `width` is thickness / L. Values are derived from the depth:length ratios in 02_fish_species §A.

### 1.2 Fins
> **As built**: fins are triangulated grids from `median_fin`, `caudal_fin` (rounded | truncate | forked | lunate), `paired_fin` (round | pointed | paddle | pelvic, optional finger lobes) and `ribbon_fin` (engineer goby). All fins of a species share one **512×256 RGBA fin atlas** with 8 slots of 256×64 (2 columns × 4 rows): 0 dorsal, 1 second dorsal, 2 anal, 3 caudal, 4 pectoral, 5 pelvic, 6 ribbon, 7 spare; in-slot coordinates are t across the fin and s from base (0) to tip (1). Rays, margins, spots and alpha are painted per slot (`paint_fin_slot`). Cirri (hawkfish, blennies) are tiny tapered quads merged into the dorsal/body mesh.

Original plan: `build_fin(points_2d, thickness=0.0, ray_count)`: a flat polygon (triangulated grid, 2-sided material, ~150–300 tris) placed on the body with `extras.part="fin"`; `Col.b` = normalized distance from the base edge (for clamping); `Col.a` = u at the base. Fin texture: a 512×256 RGBA PNG per fin set painted in Python (Pillow): base fin color with alpha 0.55, ray lines every `width/ray_count` with alpha 0.85 and 1 px width, soft edge gradient to alpha 0 over the last 6% of the span, species margin color on the outer 8%.

### 1.3 Eye
As built: 10 × 6 UV sphere (100 tris) with planar side UV and a 64×64 radial iris texture; faces within 24° of the outward axis use the black pupil material. Each eye node has `extras.pivot` (glTF-space eye centre) for swivelling. Original: UV sphere r = 0.045 L (species override) at the eye position, 2 materials: sclera/iris texture (ring colors per species) and a black pupil cap; `extras.part="eye"`. The eye is a separate mesh so the shader can swivel it (`uEyeYaw`).

### 1.4 Texture painting (`paintlib.py`)
(As built: numpy only, no Pillow in the bpy venv; PNGs are written by `common.write_png` with adaptive filters + zlib 9. Stroke-brush painting `Flank.stroke` is used for the tang palette and hawkfish bars.) Textures are generated procedurally with Pillow + numpy in the unrolled UV space (1024×512 for body; u horizontal, v vertical, v=0.5 lateral line, v=0 belly seam, v=1 back... i.e. belly at both edges). Elements: solid base, vertical bars (u ranges, soft edges 2–3% of L, slightly narrower at the belly), spots (Poisson disc samples), stripes (v bands), gradient dorsal→ventral, scale pattern overlay (hexagonal noise at 1–2% L, 6% contrast) for scaled species, mucus speck noise. Roughness is a constant per material (not a map) in v1. Normal maps: none for fish.

### 1.5 LOD and export
Each fish GLB contains one node hierarchy: `Root` → `Body` (mesh), `FinDorsal`, `FinAnal`, `FinCaudal`, `FinPectoralL/R`, `FinPelvicL/R`, `EyeL`, `EyeR`. LOD1 is produced by Decimate (**as built: body 0.3, fins 0.4, eyes 0.6**, then the body is trimmed further if the total exceeds 1650 tris; engineer goby cap 2000) and exported as a second, **self-contained** GLB `*_lod1.glb` with half-resolution textures embedded. Triangle budgets: body 3.0–4.5k, fins ≤ 1.2k total, eyes 2×96. Fish are modeled at **unit length 1.0 (L = 1 Blender unit = 1 cm × scale at runtime)** facing +X, lateral line at y=0, belly at −y; the runtime scales by `lengthCm`. As built, the whole fish from snout tip to caudal tip spans x ∈ [−0.5, +0.5] (snout +0.5), centred on the origin. `Root` extras: `species`, `lengthCm`, `iridescence`, `roughness`, `lod`, `bodyScale` (spec-u → model-x scale), `unit`; the tang adds `altTextures.adult = textures/tang_adult_albedo.png` (adult body without the juvenile yellow belly). Fish GLBs: `clown_orange`, `clown_darwin`, `tang`, `cardinal`, `wrasse`, `engineer_goby`, `hawkfish`, `lawnmower_blenny`, `tailspot_blenny`, `dottyback`, `diamond_goby` (each + `_lod1`).

### 3.2 Procedural rock method (`tools/blender/rockscape.py`)
> **As built** (differences from the steps below):
> - Blocking: the `ROCKS` table holds 3–12 ellipsoid metaballs per rock (world cm), plus **5 random flattened "plate" sub-rocks and 2 small crevice carves per element** (seeded) to break the smooth metaball silhouette into stacked rubble; R4 gained a back-glass rubble band (x 52–79, y up to 53) because the photo shows rock up to the waterline across the back. Tunnels (eel den: 9 balls r 3.8–4.5 cm; blenny hole r 1.9–2.1; tailspot hole; tang crevice) are negative balls.
> - Voxel remesh at **0.55 cm before clipping** (remeshing an open mesh collapses it), then a bisect clip at y = 0.4 (below the sand).
> - Displacement is computed in numpy (`noise3d.py`): Worley lumps + knobs + fBm + crackle + horizontal strata; **pores are KD-tree dents** (~600 spherical dents r 0.4–1.6 cm) instead of boolean spheres (booleans on an 80k-face remesh were unreliable and slow).
> - Decimate to 40k → 39.2k tris, Smart UV. Cycles bakes (EMIT position/normal 2048², AO 1024², tangent normal selected-to-active 1024²) then the albedo is **painted in numpy** from baked world position/normal/AO with the colors listed in step 6, quantized for PNG size. AO is mostly left to `rock_rough_ao.png` (only 22 % baked into the albedo) since the shader multiplies it.
> - Outputs: `rockscape.glb` (single node `Rock`, `part="rock"`, albedo RGBA embedded, alpha = hair-algae mask), `textures/rock_normal.png` (1024², tangent space), `textures/rock_rough_ao.png` (1024², R roughness, G AO).

1. **Blocking**: for each element R1–R8 create 2–6 metaballs (`bpy.data.metaballs`, resolution 1.0 cm, threshold 0.6) positioned/scaled per the table (the script holds a literal list of ellipsoid metaballs: center, radii, rotation). Negative metaballs carve the caves/arch openings (R1 cavern, R4 opening, R6 arch, R5 den tunnel: a chain of 4 negative balls r 4 cm along the den path). Convert to mesh.
2. **Remesh** voxel 1.2 cm; **Displace** ×2: Voronoi F1 (scale 6 cm, strength 1.5 cm) for lumps, Musgrave/fBm (scale 1.5 cm, 4 octaves, strength 0.5 cm) for pits; a third displace with a Voronoi "crackle" (scale 2 cm, strength −0.3 cm) for pores.
3. **Boolean holes**: scatter 150 spheres r 0.6–1.5 cm on the surface (random faces, weighted toward upward and front-facing faces) and boolean-difference them (pores up to 3 cm look). Dedicated holes: blenny hole (r 1.3 cm, 6 cm deep at the R2 position), 5 small crevices.
4. **Decimate** to 40k tris (planar + collapse), smooth shading with 45° auto-smooth.
5. **UV**: Smart UV Project (angle 66°, margin 0.002) into one 2048² atlas.
6. **Bake** (Cycles, 64 samples, CPU) albedo + AO + normal + roughness from a procedural material: base `#D8CBB0` tan with `#B9A98C` crevices (AO-driven), **green film** `#5E6B38` mix 0.5 on upward-facing areas with noise mask (this tank's rock reads green-brown), **coralline** patches `#D46A8A`/`#7F5CB5` (noise mask threshold 0.72, mostly on R1 right half, R6 and R8), **hair algae** `#3B5B2E` mask stored in the albedo alpha channel (so the shader can scale it with `uAlgaeBloom`), white `#E8E2D4` on R3's upper half and R5's front (fresh-looking rock in the photos). Roughness 0.85 ± 0.1 by noise. Output: `rock_albedo.png` 2048², `rock_normal.png` 1024², `rock_rough_ao.png` 1024² (R = roughness, G = AO).
7. Export `rockscape.glb` (single mesh node `Rock`, extras `anchor` list serialized separately).

### 5b. Life-stage body textures (`tools/blender/life_stages.py`)
Juvenile / subadult / adult / sex forms per fish (research: `docs/research/life_stages.md`). Each form is painted on the
model's own unrolled body canvas (same `Flank` as `fish_species.py`) at half the GLB body resolution and written to
`textures/stages/<model>_<form>.png`, with `textures/stages/manifest.json` mapping `models/<model>.glb` → `forms` and
`base` (the form the GLB's embedded body texture already shows; it is not written again and stays full resolution). The
GLBs are unchanged. At runtime `LifeStageVisuals` binds form A on unit 0 (or keeps the embedded albedo for the base
form) and form B on unit 15, mixed by `uStageMix` in `fish.frag`; `uStageShape` in `fish.vert` scales body depth/width
per stage (sheet `lifeStages.stages[].depthScale/widthScale`). Forms: clown orange/darwin `juvenile`; tang `juvenile`,
`adult` (no yellow belly, Tee's Pacific-form fish); cardinal, wrasse, hawkfish, lawnmower, tailspot, dottyback, diamond
goby `juvenile`; engineer goby `juvenile` (two pale stripes), `subadult` (saddles and cream bands, Tee's p02), `adult`
(mottled brown), plus fin-sheet forms (`fins.base` / `fins.forms` in the manifest, `textures/stages/engineer_goby_fin_<form>.png`): the GLB fin sheet with its yellow ticks is the `subadult` base, the juvenile gets plain black fins and the adult mottled brown ones. Pending: leopard wrasse `juvenile` / `female` / `male` (`PENDING_MODELS`, painted once
`models/leopard_wrasse.glb` exists). ≈ 1.7 MB in all.

### 8. Build order and verification
**As built**: `build_all.py [--only steps] [--skip steps] [--nobake] [--preview]` runs `selftest` → `textures` → `fish` → `inverts` → `rockscape` → `sdf` → `tank` → `corals` → `equipment` → `details` (§4.1) → `cards`, then `tools/validate_glb.py` (stdlib-only: GLB structure, required attributes, allowed parts, budgets +15 %, fish COLOR_0.a direction/monotonicity and unit extent, LOD1 caps, instance-table strides, anchors.json names, RSDF header/size, rendered-triangle estimates for the default view: **High ≤ 220k** (every LOD0 scene GLB + all polyp instances, fish at LOD1 because the default camera is > 60 cm away; the all-LOD0 worst case is printed too) and **Medium ≤ 140k** (`rockscape_lod1.glb` / `kenya_lod1.glb` substituted, the other polyp instance tables halved, fish at LOD1), assets ≤ 45 MB (raised from 35 for the HQ rock maps, then 40 → 45 for the leopard wrasse, supply shelf and new corals)). Previews use **Cycles CPU** (EEVEE needs a GPU/EGL context that the headless build machine lacks): `preview.py --fish all` → `docs/preview/fish.png` + `docs/preview/inverts.png`; `preview.py --coral kenya [--out x.png]` → a close-up of one coral GLB on the rock (app-side `CORAL_TINT` mirrored; `docs/preview/kenya_before_after.png` = clip frame / v2 / v3 / v3 LOD1); `preview.py --scene` → `docs/preview/scene.png` (the preview expands instance tables into real geometry and bends the engineer goby along the den). Full rebuild ≈ 5 min plus ≈ 5 min for the 1280×720 scene render.

Original plan: `build_all.py` runs: `fishlib` self-test → each species → `rockscape` → `corals` → `tank` → `render_cards` → `bake_sdf`. It prints per-asset triangle counts and fails if any exceeds its budget by > 15%. A `preview.py` renders a 1280×720 Eevee shot of the assembled scene from the front (camera at (61, 35, 140) cm looking at (61, 28, 16)) to `docs/preview/scene.png` for visual review against `tank_full.jpg`.
